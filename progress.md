## 1. PRODUCT [D]
- botcore = portable single-binary LLM-agent runtime. Agent `<name>.bot` = static botcore ELF + appended read-only pack (markdown + tool executables). No compiler/linker/packer inside a .bot. Keep botcore small.
- Botter (display name; binary `botter`) = meta-agent built on botcore: `mkdir x && cd x && botter` -> designs project with user, writes files, builds `./<folder>.bot`.

## 3. BUILD + TOOLS [D, DONE]
- `botter_pack build|check|list`. Format (authoritative src/blob.h, packer has a copy): `[botcore ELF][pad 4096][BLOB "BOTBLOB1" sorted entries][FOOTER 32B crc32 "BOTPACK1"]`. Loader reads /proc/self/exe footer, mmap RO; bad footer = refuse start. Pack reference (blob.h): 32B "BOTPKREF" + blob_off + file_size inside the botcore ELF data, patched by botter_pack per build; zero = plain botcore; size mismatch / missing footer with a patched ref -> "this agent file is truncated|damaged: it should be N bytes" (truncation inside the ELF itself still just crashes).
- Errors: tool w/o descriptor, non-x86-64 ELF, bin neither ELF nor #!, bad name. Warnings: dynamic ELF, descriptor w/o bin, missing agent.md, leftover manifest.md, Sqnc warnings (Sqnc errors stop the build).
- Tool protocol: args = one JSON object on stdin (argv empty); stdout result; exit!=0 = error (stderr). Run from memfd+fexecve in sandbox child (setsid, cwd=ctx, rlimits, killpg on timeout/Ctrl-C, 32KB cap). fd 3 = agent's own exe (BOTCORE_RUNTIME_FD) so agent_build can use it as runtime.
### 3a. Network mode [D 2026-10-09]
- ONLINE by default (botter + built agents): shell_exec/tools keep host network, network cmds allowed, `git push` asks, no consent prompt/probe.
- `config.json "internet": false` (invalid JSON => offline): children in empty netns (userns) else seccomp (blocks AF_INET/INET6/PACKET); guard denies curl/wget/pip/docker/git clone...; per-tool `"network": true` exception after startup y/N consent. Botter adds "offline" to agent.json ONLY on explicit user request.
- LLM calls are made by the botcore parent: never sandboxed, always work.
### 3b. SQNC.md / Sqnc [D owner 2026-10-09; was OML v2 / flow.md]
- Name: Sqnc ("sequence") [D owner]; file SQNC.md [D owner]. "OML" dropped: clashes with Orchestra Markup Language (.oml, Oct 2026). Syntax from a Gemini-suggested example; research found no existing use (PDL YAML, POML, BWML XML, SudoLang, gh-aw prose).
- File [D owner 2026-10-09]: the WHOLE file is one ```sqnc block: line 1 ```sqnc, then frontmatter (spec-version "sqnc-1" required; title, description), statements, last line ```; nothing after it. No Markdown inside: # lines and <!-- --> are errors (## STEP gets "write STEP n: NAME"); every non-statement line is an instruction. STEP n: NAME is a statement (label, numbered in order, warning otherwise). Statements: STEP, LOAD SKILL, EXECUTE tool `t` [with payload {..} | with parameters: + "- k: v" | prose], INVOKE SKILL "n" USING context .., ASK USER .., SAVE x INTO VARIABLE `v` | TO FILE "rel", SET `v` TO, IF/ELSE IF/ELSE/END IF, FOR EACH `x` IN .. DO/END FOR, WHILE .. AT MOST N TIMES DO/END WHILE, RETRY UP TO N TIMES DO/END RETRY, IN PARALLEL DO/END PARALLEL, RETURN. CONNECT (MCP) -> error. OML v1/oml-2 legacy checks removed.
- Front end botcore/src/sqnc.c + sqnc.h (shared; packer #includes it): sq_parse -> AST + syntax errors (frontmatter, fences, block matching with recovery, statement forms, quotes/backticks/payload brackets, RETRY 1..20, WHILE AT MOST 1..1000, keyword typos); sq_check (packer only): tools exist (built-ins + tools/bin; sqnc_review only if config.json builder), skills exist + LOADed before INVOKE, variables set before use, FOR var scoped, result/skill_output/answer after producers. Diagnostics "SQNC.md:LINE: error|warning: msg" (param lines carry their own line). Errors stop check/build.
- Interpreter botcore/src/sqnc_run.c [D owner: "write the interpreter, Sqnc is a language for LLMs"]: runs at agent start (after Connected; TUI gets {"ev":"flow"} so the first-message clear keeps the flow's output), /run restarts, chat continues after. Values = cJSON. Deterministic in botcore: EXECUTE (payload template with `refs`/bare keys -> JSON; params; prose args -> LLM builds JSON from the tool schema), ASK USER (question shown as agent message, answer via the chat prompt, "[N] " tag stripped, commands work there), SAVE/SET, literal expressions ("str" + `ref` + numbers; `x.length`), conditions with IS EQUAL TO / IS NOT EQUAL TO / IS GREATER THAN / IS LESS THAN / CONTAINS / IS EMPTY / IS NOT EMPTY / AND / OR / NOT, FOR EACH (array/object/JSON text/lines, cap 1000), WHILE (default cap 100), RETRY (body restarts on a failed step: tool ERROR or LLM reply starting FAILED), IN PARALLEL (sequential for now), SAVE TO FILE (inside ctx, refused in Plan), RETURN literal. LLM: plain-English lines + INVOKE SKILL = io->turn (chat_send with tools, shown, "[Sqnc step, line N] ..." + notes since last step + variables), prose values/conditions/args = chat_ask (history as context, no tools, history unchanged). FLOW_HINT tells the model about [Sqnc] steps.
- Logic review: built-in tool sqnc_review (tool_review.c), registered only for config.json "builder": true (Botter): parses, then chat_ask fresh with REVIEWER prompt + agent.md + skill descriptions + tool docs + numbered SQNC.md -> JSON {makes_sense, summary, problems[{line, statement, why, suggestion}], report}. Botter's SQNC.md runs it after dry_run passes and asks the user before applying suggestions.

## 5. CONSTRAINTS [D]
ZERO DISK PERSISTENCE by runtime (no config/logs/cache files; history RAM-only; only files the task creates). Cron RAM-only, fires at idle prompt. Memory feature deferred.
- [D 2026-10-09 owner] Key cache until reboot: keystore.c, kernel user keyring (@u) entries "botcore:{key,model}:<base>" + "botcore:last" (base), perm possessor-only (0x3f010000). Start: connect_saved() reconnects silently to last base/model (auth fail -> key blanked, normal flow); connect flow offers saved key ("Enter = saved key") and model per base. /provider = connect_flow + chat_switch (keeps history; strips non-standard tool_call fields when base changes), /forget = ks_forget_all, /help. Children: ks_child_lock (anon session keyring) + seccomp ENOSYS on add_key/request_key/keyctl (skipped only for approved sudo). BOTCORE_NO_KEYRING=1 off; BOTCORE_KEYRING_NS=<ns> (tests). Gone at reboot or when the user's last process exits.
- [D 2026-10-09 owner] Streaming: chat requests "stream": true whenever an event callback is set (always now); http_request_stream passes de-chunked body bytes to a callback (2xx only, Accept: text/event-stream). chat.c stream_t: SSE lines -> delta.content through a <think>/<thinking>/<thought> filter (text vs reasoning, close tag held back across chunks), reasoning_content/reasoning -> think deltas, tool_calls merged by index (else id; args concatenated, other keys latest-wins so Gemini extra_content survives), "error" object -> failure; result rebuilt as a plain {"choices":[{"message"}]} so the old path runs unchanged; endpoint that sent plain JSON parsed as before; 400 -> drop thoughts, then no_stream retry. Events CHAT_EV_TEXT_DELTA/THINK_DELTA; frontend {"ev":"delta","kind":"text|thinking"}; TUI appends to open block, final text/reply replaces it, streams reset at next prompt. REPL prints deltas, never reasoning; Gemini include_thoughts only in the UI (chat_set_events 4th arg).
- [D 2026-10-09 owner] Users never see tool names: tool event carries "status" (built-in map in main.c tool_status, descriptor "status" for agent tools, default "Working"); TUI hides tool blocks unless ctrl+o (details) and shows the status in the busy line ("Writing" while text streams); REPL prints "  · <status>", /details shows raw calls. Approval prompts still show the real command.
- [D 2026-10-09 owner] Plan/Build modes (OpenCode-style): guard_set_plan/guard_plan. Plan: fs_write + cron_set refuse (GUARD_PLAN_REFUSAL), Landlock ctx RO (scratch dirs containing ctx RO too; approved grants RO), approved-sudo refused, Plan without Landlock refuses to run children, ext tools ask unless descriptor "readonly": true (agent_inspect has it). Model told via MODE_HINT in system prompt + "[Mode: PLAN|BUILD ...]" note prepended to the first user msg after a change. REPL: /plan /build /mode, "plan >>" prompt. TUI: Tab toggles (queued if busy), {"ev":"mode"} event, label in input box border; slash commands are no longer numbered/shown as user messages.

## 6. SAFETY MODEL
Free inside ctx (cwd at launch); ask y/N before outside-ctx access or destructive ops. LLM output untrusted.
- L1 path guard (fs_*: realpath vs ctx) DONE. L2 shell classifier (soft) DONE: confirms rm/dd/kill/sudo/`sh -c`/`$()`/overwrites/outside paths/destructive git/git push; offline adds network-cmd deny.
- L3 Landlock [DONE Ph3d] for every child (shell_exec + tools), all agents: RW ctx, /tmp, /var/tmp, /dev, ~/.cache, ~/.npm; RO+exec system dirs (/usr /etc /proc /sys /run /var /opt ...), $PATH dirs + their prefix if .../bin (not $HOME or /), ~/.gitconfig. Rest of $HOME hidden. Approved shell command naming outside paths -> those paths (or deepest existing parent) granted RW for that run only; approved sudo -> no Landlock that run. ABI probed (1..5 rights); unavailable -> dim note; apply failure -> refuse (fail closed). Needs no_new_privs (setuid can't elevate except approved-sudo runs). Runtime fd 3 opened before sandbox.
- L4 rlimits: CORE 0, FSIZE 1GiB, CPU timeout+5, NPROC = user's procs at startup + 1024 (fork-bomb brake), DATA = physical RAM (chosen over AS: AS breaks V8/Go/WASM reservations). L5 network isolation: offline agents only (§3a).
- Key: RAM-only, never argv/env/disk; mlock'd + explicit_bzero on free; process PR_SET_DUMPABLE 0 (no ptrace/proc mem by same user; netns child re-enables before unshare, else uid_map is root-owned).

## 8. ISSUES
Resolved I1 (Ph4): no host curl. Limits: TLS 1.2 only (BearSSL has no 1.3; all presets fine); IP-literal HTTPS hosts fail name check; DNS (getaddrinfo) not interruptible by Ctrl-C; corporate MITM CAs unsupported (no custom CA option yet).
P1 I4 Classifier bypassable (`python -c`); hard layers cover fs (L3) and offline net (L5). An approved new-file path grants its existing parent (often $HOME) RW for that run.
P2 memfd exec may be blocked by confined SELinux / vm.memfd_noexec (no fallback). Editor width = codepoints (CJK). Streaming verified only against the local stub (no real-provider key in tests).
