## 1. PRODUCT
botcore = [D] the CORE HARNESS of the botter framework: portable single-binary LLM-agent RUNTIME that botter attaches an agent bundle (markdown + compiled C tools) to, plus the external LLM, when the user "compiles" the agent. Feel: code an agent in markdown + some C, compile -> one self-sufficient self-contained agent binary.
AGENT (`<name>.bot`) = prebuilt static botcore ELF + appended read-only agent pack (markdown + embedded tool executables). No compiler or linker is involved anywhere; no packer inside the .bot.
`botter` = meta-agent that authors/compiles other agents (the "framework"). Workflow:
  mkdir myagent && cd myagent && botter -> scaffolds project -> user+LLM iterate on md/tool code -> "build" -> `./<rootfolder>.bot` in cwd root; runs on any x86_64 Linux.

## 2. PROJECT LAYOUT [D, revised 2026-10-08]
```
<agent>/
  manifest.md        LLM-facing map (package.json-like: skills, tools, relations). botter generates+maintains; humans may edit
  agent.md           persona, character, behaviour, expectations -> system prompt
  skills/<n>/SKILL.md  task playbooks: how/when to use tools
  tools/             OPTIONAL, advanced users; average users delete it
    bin/<name>       the runnable tool, embedded: native ELF x86-64 (compiled by the user from ANY language) OR a script starting `#!`
    doc/<name>.json  machine descriptor (REQUIRED per bin): {"description": str, "parameters": JSON-Schema object (optional), "timeout_s": int (optional, default 60, max 600)}
    doc/<name>.md    human/LLM prose docs (examples, caveats); free-form, read by the LLM via vfs_read
    src/             source of COMPILED tools only. NEVER embedded, NEVER deleted [D]; lives in the agent's git repo
  artifacts/         build-time inputs, never embedded (botter's own: `botcore` static ELF, `botter_pack`)
```
Interpreted tools need no src/: the script in tools/bin IS the source and the runnable. Compiled tools: source in tools/src, user builds into tools/bin (bin may be git-ignored). Tool name = file name = [A-Za-z0-9_-]{1,64}; must not clash with a built-in tool.
Embedded in the .bot (read-only): manifest.md, agent.md, skills/**, tools/doc/**, tools/bin/*. Not embedded: tools/src, artifacts/, hidden files, symlinks. src.zip DROPPED [D].
- VFS [DONE]: `src/vfs.{c,h}`: table of `vfs_entry_t{path,data,len,kind}` sorted for bsearch, `vfs_init()` loads the pack from the file's own trailer (below), `vfs_find`. Tools `vfs_list`/`vfs_read` registered only if a pack exists; they hide/refuse tool executables (kind != data). 32KB cap + offset, UTF-8-safe cut. System prompt = embedded `agent.md` (else a built-in default) + cwd + offline/permission text + hint to read manifest.md.

## 3. BUILD MODEL [D 2026-10-08: NO COMPILER SHIPPED; tools are external programs; IMPLEMENTED]
Owner decisions: botter ships no compiler/linker. Users bring their own tools in any language (compiled binary = portable; script = user ensures the interpreter exists on the target). Output = `<rootfilename>.bot` [D]. Temp writes at botter build time OK [D].
BUILD = pure file ops (`botter_pack build <agent-dir> <botcore-static> <out.bot>`, botter will extract artifacts/botcore to temp first): copy botcore -> zero-pad to 4096 -> BLOB -> FOOTER -> chmod 755 (atomic rename). Packer refuses a botcore that already has a pack, an ELF tool that is not x86-64, a script/ELF-less bin file, a tool without descriptor. Warns: dynamic botcore, dynamic ELF tool, descriptor without bin, missing agent.md/manifest.md.
FORMAT (authoritative: `src/blob.h`; botter_pack carries its own copy; bump magic digits on change): `[botcore ELF][pad][BLOB][FOOTER 32B]`. BLOB = "BOTBLOB1", u32 count, entry[32B each: path_off,path_len,data_off,data_len,kind] sorted strictly ascending, strings, data (each NUL-terminated). FOOTER = blob_off u64, blob_len u64, crc32 u32, rsvd u32, "BOTPACK1". Loader: open `/proc/self/exe` (fallback `getauxval(AT_EXECFN)`), pread footer, validate bounds + crc32 + sorted index, mmap read-only (no copy). No footer = plain botcore (no pack, default prompt). Footer present but invalid = refuse to start ("embedded agent pack is damaged"). Known gap: a .bot truncated so the footer is gone silently looks like plain botcore.
TOOL PROTOCOL [DONE, owner picked "embedded, run from memory"]: `src/tool_ext.c`. Args = one JSON object on stdin; stdout = result; exit 0 = ok; non-zero = error (stderr, else stdout, becomes the error text; "[tool X exited with code N]"). Runs in forked child with the SAME sandbox as shell_exec (`tool_sandbox_apply`: setsid, cwd = context dir, rlimits CORE/FSIZE/CPU, empty netns L5 fail-closed), via `memfd_create` + `fexecve` (ELF: MFD_CLOEXEC; script: memfd left open because the kernel passes /proc/self/fd/N to the interpreter). Timeout (descriptor, default 60s, max 600) kills the process group; Ctrl-C kills; crash by signal reported; output cap ~32KB with truncation note; stderr kept 2KB. Script interpreter (`#!/path/x` or `#!/usr/bin/env x`) is checked on the host before each run -> clear "needs 'x', which is not installed on this machine". Startup warnings (dim) for tools skipped: bad name, clash with built-in, missing/invalid descriptor.
Tested 2026-10-08 on F44 enforcing (unconfined_t) with static-musl botcore: ELF tool (musl static), python3 script w/ JSON stdin, sh script nonzero exit + stderr, SIGSEGV tool, 10s sleep vs 1s timeout, missing interpreter, network from tool blocked (ENETUNREACH), 100KB output truncation, vfs_read refuses executables, dynamic-glibc botcore + pack also works. Via mock OpenAI server only (not real LLM).
Open risks: confined SELinux domains / `vm.memfd_noexec` / noexec /proc could block memfd exec (no fallback implemented; would need temp-file exec = zero-persistence exception, ask owner); containers w/o /proc (loader fallback exists, memfd exec needs /proc/self/fd for scripts); static ELF tool recommended for portability.

## 6. SAFETY MODEL [D] (enforcement = [R])
Policy: free inside context dir; ASK user (tty y/N) before (a) any access outside context dir, (b) destructive/irreversible ops. LLM output is untrusted; prompt-only is not a boundary. Layers:
- L1 path guard (hard): fs_* tools use realpath()/openat2 RESOLVE_BENEATH vs context dir; outside -> confirm gate.
- L2 shell gate (soft): tokenize shell_exec; classify destructive (rm, rmdir, mv/cp overwrite, dd, mkfs, chmod/chown -R, truncate, `>` onto existing file, find -delete, git clean/reset --hard, sudo, kill*, shutdown) and outside paths -> confirm. Unparseable => risky. Also DENYLIST network tools with clear error: curl wget ssh scp sftp rsync nc ncat socat telnet ftp ping dig nslookup host git{clone,fetch,pull,push,remote} pip npm cargo dnf yum apt.
- L3 filesystem (hard) [S]: per-call child gets Landlock ruleset (Fedora kernel supports): RW context dir (+approved grants), RO system dirs. Denial -> error to LLM -> LLM asks -> user approves -> next call wider ruleset.
- L4 resources: child rlimits (CPU, AS, NPROC, FSIZE), timeout, killpg, output cap.
- L5 network (hard) [R]: child does `unshare(CLONE_NEWUSER|CLONE_NEWNET)` -> empty netns (loopback only), kernel-enforced, covers TCP/UDP/DNS, unprivileged on Fedora. Fallback: seccomp-bpf denying socket(AF_INET|AF_INET6|AF_PACKET|AF_NETLINK). Landlock net rules alone insufficient (TCP only, no UDP). Parent runtime process alone keeps network (LLM HTTPS). Apply to shell AND forked tool calls. Note: SELinux enforcing may restrict userns on some policies [S verify].
shell_exec = fork + execve `/bin/sh -c`, own pipes, setsid (implemented, no popen).
